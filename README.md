# tor-router

Скрипт для перенаправления трафика к выбранным сайтам (по домену или IP/CIDR)
через сеть Tor с помощью firewall-правил (`nftables`, с fallback на `iptables`).

Правила живут в отдельной таблице/цепочке `tor_router` — основной firewall
не трогается. `restore` полностью удаляет эту таблицу/цепочку, возвращая
систему в исходное состояние.

## Требования

Проверяются автоматически при каждом запуске (см. `check_dependencies` в
скрипте) — если чего-то не хватает, скрипт покажет, что именно поставить,
и остановится:

- `sudo`
- `tor`
- `getent`, `grep`, `sed`, `awk`, `id`, `ps`
- `nft` **или** `iptables` (нужен хотя бы один)

## Структура

```
tor-router/
├── tor-router.sh              # единый скрипт: конфиг + вся логика
└── completion/
    └── tor-router-completion.bash   # bash-автодополнение
```

Конфиг и данные создаются автоматически при первом запуске:

```
~/.config/tor-router/tor-router.conf   # настройки (генерируется из самого скрипта)
~/.config/tor-router/sites.list        # список сайтов
~/.local/state/tor-router/active_ips.cache   # кеш резолвинга
```

## Sudo — только там, где реально нужно

Сам скрипт **не требует запуска через `sudo` целиком**. Команды, не
трогающие firewall/Tor (`add`, `remove`, `list`, `help`), выполняются как
обычный пользователь без единого запроса пароля.

Команды, которым нужны привилегии (`setup`, `apply`/`refresh`, `restore`,
`status`), сами вызывают `sudo` точечно — только на реальных системных
действиях (запись правил firewall, изменение `/etc/tor/torrc`, рестарт
сервиса). Пароль спрашивается один раз за сессию (`sudo` кеширует его на
~15 минут), дальше используется кеш.

Если запустить весь скрипт под root (`sudo ./tor-router.sh ...`) — тоже
работает: скрипт видит, что уже root, и просто не вызывает `sudo` повторно.

## Быстрый старт

```bash
chmod +x tor-router.sh

# 1. Один раз: настроить torrc (TransPort/DNSPort) и перезапустить Tor
#    (сам запросит sudo, когда понадобится)
./tor-router.sh setup

# 2. Проверить, от какого пользователя реально работает демон tor,
#    и при необходимости поправить TOR_USER в ~/.config/tor-router/tor-router.conf
ps -o user= -C tor

# 3. Добавить сайты — без sudo
./tor-router.sh add example.com
./tor-router.sh add 203.0.113.0/24

# 4. Посмотреть список — без sudo
./tor-router.sh list

# 5. Применить маршруты — запросит sudo
./tor-router.sh apply

# 6. Посмотреть активные правила
./tor-router.sh status

# 7. Откатить всё обратно
./tor-router.sh restore
```

## Команды

| Команда | Нужен sudo | Описание |
|---|---|---|
| `setup` | да (точечно) | добавляет `TransPort`/`DNSPort` в torrc, перезапускает Tor |
| `apply` / `refresh` | да (точечно) | резолвит домены из `sites.list`, создаёт правила редиректа в TransPort |
| `restore` | да (точечно) | удаляет таблицу/цепочку `tor_router` целиком |
| `status` | да (точечно) | показывает текущие правила |
| `list` | нет | показывает `sites.list` |
| `add <domain\|ip>` | нет | добавляет запись в `sites.list` |
| `remove <domain\|ip>` | нет | убирает запись из `sites.list` |

`add`/`remove` только редактируют конфиг — чтобы правила фаервола
обновились, нужно затем выполнить `apply`.

## Автодополнение в bash (Tab)

Добавьте в `~/.bashrc`:
```bash
source /полный/путь/до/tor-router/completion/tor-router-completion.bash
```
Затем `source ~/.bashrc` или откройте новый терминал. После этого:

```bash
./tor-router.sh <Tab><Tab>          # покажет: setup apply refresh restore status list add remove help
./tor-router.sh rem<Tab>            # -> remove
./tor-router.sh remove <Tab><Tab>   # подставит текущие записи из sites.list
sudo ./tor-router.sh remove gi<Tab> # работает и через sudo
```
Для `add` подсказок нет намеренно — значение произвольное (домен/IP/CIDR).

## Важные ограничения (честно, как есть)

1. **Домены матчатся по IP, а не по SNI/Host.** Скрипт резолвит домен один
   раз при `apply` и редиректит именно эти IP. Если у сайта много IP за
   CDN (Cloudflare, Fastly и т.п.) или адрес поменялся — вызывайте
   `refresh` заново, иначе часть трафика может пойти в обход Tor. Для
   доменов за большими CDN (Cloudflare/Fastly/Akamai) вписывать их
   диапазоны IP не стоит — это огромные общие блоки на тысячи чужих
   сайтов, лучше полагаться на периодический `refresh`.
2. Redirect выполняется в `OUTPUT`-цепочке — то есть перенаправляется
   именно **исходящий с этого ПК** трафик (не форвардинг через ПК как
   роутер для других устройств).
3. Anti-loop правило исключает трафик самого процесса `tor` (по uid из
   `TOR_USER` в конфиге) — если uid указан неверно, Tor не сможет выйти в
   сеть. Проверяйте `ps -o user= -C tor`.
4. Если домен временно не резолвится (DNS-сбой, опечатка), скрипт
   выводит предупреждение и пропускает его, продолжая с остальными —
   не прерывает весь `apply` целиком.
5. Тестируйте на непринципиальной машине/VM перед боевым использованием —
   ошибка в правилах output-редиректа теоретически может временно
   заблокировать исходящий трафик до `restore`.
