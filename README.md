# tor-router

Скрипт для перенаправления трафика к выбранным сайтам (по домену или IP/CIDR)
через сеть Tor с помощью firewall-правил (`nftables`, с fallback на `iptables`).

Правила живут в отдельной таблице/цепочке `tor_router` — основной firewall
не трогается. `restore` полностью удаляет эту таблицу/цепочку, возвращая
систему в исходное состояние.

## Требования

Проверяются автоматически при каждом запуске (`check_dependencies`) — если
чего-то не хватает, скрипт покажет, что именно поставить, и остановится:

- `sudo`, `tor`, `realpath`
- `getent`, `grep`, `sed`, `awk`, `id`, `ps`
- `nft` **или** `iptables` (нужен хотя бы один)

## Структура пакета

```
tor-router/
├── tor-router.sh                     # единый скрипт: конфиг + вся логика
├── completion/
│   └── tor-router-completion.bash    # bash-автодополнение
└── icons/
    └── tor_router_apply.svg          # (опционально) своя иконка для .desktop-ярлыка
```

Запускайте `--install` из этой распакованной папки, а не из уже установленной
копии — иначе автодополнение и иконка не найдутся (сама установка скрипта
при этом всё равно отработает).

Конфиг и данные создаются автоматически при первом запуске:

```
~/.config/tor-router/tor-router.conf   # настройки (генерируется из самого скрипта)
~/.config/tor-router/sites.list        # список сайтов
~/.local/state/tor-router/active_ips.cache   # кеш резолвинга
```

## Sudo — только там, где реально нужно

Скрипт **не требует запуска через `sudo` целиком**. Команды, не трогающие
firewall/Tor (`add`, `remove`, `list`, `help`), работают как обычный
пользователь без единого запроса пароля. Команды, которым нужны привилегии
(`setup`, `apply`/`refresh`, `restore`, `status`), сами вызывают `sudo`
точечно — только на реальных системных действиях.

## Установка (`--install`)

```bash
./tor-router.sh --install ~/bin
# или без аргумента — предложит путь по умолчанию ($HOME/bin)
./tor-router.sh --install
```

Что делает:
1. Копирует сам скрипт в указанный каталог (создаст каталог, если его нет —
   спросит подтверждение).
2. Если там уже есть конфиг — предложит оставить, перезаписать (`-wc`) или
   удалить (с переносом в `<файл>.old.<timestamp>`).
3. Создаёт `.desktop`-ярлык (`~/.local/share/applications/tor-router-apply.desktop`)
   для команды `apply` — без внешних зависимостей, генерируется прямо в
   скрипте. Если рядом лежит `icons/tor_router_apply.svg` — использует её,
   иначе берёт системную иконку `security-high`.
4. Копирует `completion/tor-router-completion.bash` в
   `~/.local/share/tor-router/` и **один раз** (идемпотентно, без дублей при
   повторных установках) подключает её через `~/.bashrc`.

## Команды

| Команда | Нужен sudo | Описание |
|---|---|---|
| `setup` | да (точечно) | добавляет `TransPort`/`DNSPort` в torrc, перезапускает Tor |
| `apply` / `refresh` | да (точечно) | резолвит домены из `sites.list`, создаёт правила редиректа в TransPort |
| `restore` | да (точечно) | удаляет таблицу/цепочку `tor_router` целиком |
| `status` | да (точечно) | показывает текущие правила |
| `list` | нет | показывает `sites.list` |
| `add <domain\|ip>` | нет | добавляет запись в `sites.list` |
| `remove <domain\|ip>` | нет | убирает запись из `sites.list` |
| `-h`, `--help`, `-u`, `--usage`, `help` | нет | справка |
| `-V`, `--version` | нет | справка + версия/changelog/copyright |
| `-wc`, `--write-conf` | нет | перезаписывает `~/.config/tor-router/tor-router.conf` из встроенного шаблона |
| `--install [<path>]` | нет* | устанавливает скрипт, ярлык и автодополнение (см. выше) |

\* сама установка не требует root, но `read`-запросы (перезапись файла и
т.п.) интерактивны.

`add`/`remove` только редактируют конфиг — чтобы правила фаервола
обновились, нужно затем выполнить `apply`.

## Автодополнение в bash (Tab)

Ставится автоматически через `--install`. Вручную — добавьте в `~/.bashrc`:
```bash
source /полный/путь/до/tor-router/completion/tor-router-completion.bash
```

```bash
./tor-router.sh <Tab><Tab>          # все команды и ключи, включая -V --version -wc --install
./tor-router.sh rem<Tab>            # -> remove
./tor-router.sh remove <Tab><Tab>   # подставит текущие записи из sites.list
./tor-router.sh --install <Tab>     # подставит каталоги файловой системы
sudo ./tor-router.sh remove gi<Tab> # работает и через sudo
```

## Важные ограничения (честно, как есть)

1. **Домены матчатся по IP, а не по SNI/Host.** Резолвится один раз при
   `apply`; для CDN-доменов (Cloudflare/Fastly/Akamai) IP может меняться —
   вписывать их диапазоны не стоит (огромные общие блоки на тысячи чужих
   сайтов), лучше полагаться на периодический `refresh`.
2. Redirect — в `OUTPUT`-цепочке: перенаправляется исходящий с этого ПК
   трафик, а не форвардинг через ПК как роутер для других устройств.
3. Anti-loop правило исключает трафик процесса `tor` по uid из `TOR_USER` —
   если он указан неверно, Tor не сможет выйти в сеть. Проверяйте
   `ps -o user= -C tor`.
4. Если домен временно не резолвится, скрипт предупреждает и пропускает
   его, не прерывая весь `apply`.
5. `--install` ищет `completion/` и `icons/` **рядом с тем файлом, который
   сейчас исполняется** (через `realpath`) — при повторном запуске уже
   установленной копии (без этих папок рядом) он корректно пропустит их,
   не сломавшись, но и не обновит.
6. Тестируйте на непринципиальной машине/VM перед боевым использованием.
